# GitHub Actions — бюджет минут (global)

Включённые минуты тарифа — **одна корзина на все репозитории аккаунта** за месяц
(Free 2 000, Pro 3 000; Linux ×1, Windows ×2, macOS ×10). Конец корзины =
Actions встают **везде** до оплаты. 19.08.2026 так и случилось: два репозитория
сожгли 2 000 минут за 19 дней — один из них красным CI, который никто не читал.

## Что реально тратит минуты

- Каждый push в **открытый PR** и каждый push в **main** = прогон. Push в ветку
  без PR — бесплатно.
- Биллятся **джобы, не прогон**: три параллельных джоба по 5 минут = 15 минут.
- Красный прогон стоит столько же, сколько зелёный. Красный CI, который не чинят,
  — минуты за ноль информации.
- Джоб без `timeout-minutes` при зависании живёт 6 часов.
- Сборка, которую уже делает платформа (Vercel, EAS), в CI — вторая копия того же
  гейта за те же минуты.
- Артефакты и кеши — хранилище (отдельный лимит); macOS-раннеры — ×10.

## Как работает сессия

1. **Гейт один раз.** Проверка бежит на PR. Push в main не должен гонять всё
   заново — там только то, что PR не может (миграции, деплой), и только когда
   менялись соответствующие пути. Если main всё же перепроверяется (нет branch
   protection) — хотя бы без сборки.
2. **Локально зелёный → потом в PR.** Перед `gh pr create` и перед push в открытый
   PR: type-check, lint, тесты локально. Красный прогон = выброшенные минуты.
3. **Коммиты копим, в PR пушим пачкой.** Push в открытый PR — когда пакет готов,
   не на каждый коммит. Бэкап-ветка без PR — сколько угодно.
4. **Docs-only — без CI.** Правки только `*.md` / `docs/**` не должны запускать
   прогон: `paths-ignore` в воркфлоу, а при его отсутствии — `[skip ci]` в
   сообщении коммита.
5. **Перезапуск — только упавший джоб.** `gh run rerun <id> --failed`, не весь
   воркфлоу. «Re-run, вдруг пройдёт» без найденной причины — запрещено.
6. **Красный ≥ 3 прогона подряд — стоп.** Либо чинится следующим коммитом, либо
   `gh workflow disable "<name>"` до починки. Оставить красный воркфлоу
   «на потом» — нельзя: он будет бежать на каждый push.
7. **Не гейт — не в Actions.** Сборка, которую делает Vercel/EAS; Lighthouse на
   каждый PR; iOS-сборки на macOS-раннерах; бенчмарки — `workflow_dispatch`,
   расписание раз в неделю или локально.
8. **Новый воркфлоу — только по шаблону** `templates/ci-minimal.yml`:
   `concurrency` + `cancel-in-progress` для PR, `timeout-minutes` на каждом
   джобе, кеш зависимостей, `ubuntu-latest`, `retention-days` у артефактов.
9. **Крон-воркфлоу — аудит.** `schedule` бежит на default-ветке и у забытых
   репозиториев тоже. Есть Vercel Cron / внешний пингер — лучше там.
10. **Перед правкой любого `.github/workflows/*` — посмотреть расход** (ниже) и
    сказать в отчёте, на сколько минут в месяц правка меняет счёт.

## Проверка расхода

```bash
bash ~/2111framework/scripts/gh-actions-usage.sh            # текущий месяц, все репо
bash ~/2111framework/scripts/gh-actions-usage.sh 2026-08    # конкретный месяц
bash ~/2111framework/scripts/gh-actions-usage.sh 2026-08 --exact   # точные биллинг-минуты по джобам
```

Итог тарифа: github.com/settings/billing (API `users/<login>/settings/billing/actions`
требует scope `user`: `gh auth refresh -h github.com -s user`).
Смотреть раз в неделю при активной разработке и всегда перед тем, как трогать CI.
